· 载体:本块画 standalone(添加到主屏幕后全屏启动)与普通移动浏览器 —— 顶部只剩「状态栏 59 · 不可控」,4a–4u 那条「微信导航栏 44 · 不可控」不存在。整屏内容因此比 4k / 4r 上移 44,可视高 708 → 752。59 / 34 / 752 三个数都不是常量:实现按 100dvh 与 env(safe-area-inset-*) 取,画板只是示意。

· 条高含安全区:Tab Bar 的玻璃盒子高 = 49 + safe-area-inset-bottom,四格内容只占上面那 49,底下那段是留白 —— 文字与图标不落进 Home Indicator。内容区底部内边距因此是 49 + 安全区(画板 83),与 Tab Bar 是否收起无关:收起是 transform 位移,不改变文档流的底部留白,否则每次收起都会引起一次重排。
· 收起 = 位移整条:translateY 的量 = 条整高(49 + 安全区),不是 49。现状那条 26 高残条正是量取错的结果。缓动沿用 4a 的 .25s cubic-bezier(.32,.72,0,1);收起后屏底只剩 Home Indicator 留白,不留任何半透明残条。
· 备案两行为什么各占一行:390 宽减去左右 16 只剩 358,两个号并排(mono 11 约 152 + 198 + 图标 18 + 间距)要 380 以上,必然挤成两行折行或被截断 —— 折行的号码读不出来,截断违反可见性。桌面底栏仍是并排一行,本轮不动桌面一个像素。
· 页尾不是分组卡:它是页尾小字 —— 不加 r16 卡、不加分隔线、不加「备案信息」这类标题。两行都可点(ICP → 工信部、公安号 → 公安备案系统),命中区各 390×44(整行),视觉上仍是 mono 11 #9ca3af 的两行小字。间距:导流句 ↓ 24 → 首行 44 → 次行 44 → ↓ 16 → 内容区底(其下是 Tab Bar 的 49 + 安全区)。
· 顺序上的唯一调整:4r 里「外观」排在技术栈之后;此处「外观」上移到技术栈之前,让技术栈 + 导流句 + 页尾连成收尾(桌面 2e 也是技术栈 + 导流句收尾)。块内排版一个像素不动,这是本轮唯一一处内容顺序调整。

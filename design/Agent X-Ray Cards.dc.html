2s · 裁定
· 这是第二种卡,不是第三种视觉语言。工具卡 = 「agent 做了什么」(带工具名 / 入参 / 耗时 / 状态色),信息卡 = 「agent 给你看什么」。外框一律照 2m 的卡片展开体:r6 + rgba(0,0,0,.03) 底 + 1px #e0e0e0 描边,与工具卡的区别只有一条 —— 描边用中性 #e0e0e0,不用工具卡的状态色(绿 / 红)。卡片里一处不用语义色:数据里没有「红 = 差」这种字段,染色就是编造。
· 标题行:可选。规格 = mono 10/600 #9ca3af 0.08em,与展开体的 INPUT / RESULT 同一枚。collapsed 卡的标题行不可省 —— 它是收起态唯一的把手,行首挂 12px 箭头(stroke #9ca3af,› 收起 / ˅ 展开,与 2l 折叠行、工具卡箭头是同一个图标)。
· 六种主体的解剖与上限:① stat 2–4 格一排,大数字 mono 22/650 tabular + 单位 12 #6b7280 + 标签 12 #1a1a1a + note 11 #9ca3af,格间用表格的 1px #e0e0e0 竖分隔;② kv ≤ 20 行,键列定宽 150 次级色 / 值列正文色,行间 1px #e0e0e0;③ table ≤ 6 列 × 20 行,照 2c 的 markdown 表格(表头 #f5f5f5 底 600、行 1px #e0e0e0 分隔、单元格 padding 8/12、13px),数字列走 mono tabular;④ list 有序 / 无序,序号 mono 13 #9ca3af 定宽 22,每项一行 13/1.7 正文 + 可选一行 11 note;⑤ compare 3 列 ≤ 20 行,首列(维度)#6b7280,后两列正文色;⑥ tabs ≤ 5 个,每页装上面五种之一、不能再套 tabs。所有主体的字段都是字符串 ≤ 200 字,不解析 markdown —— 卡里没有加粗 / 内联代码 / 链接语法。
· table 的外框就是表格的外框:表格全出血,靠卡片自己的 1px 描边当外边线,不再套第二层 border(套了会出双线)。表头两侧不留卡片内边距,单元格 padding 8/12 是唯一的横向留白。
· tabs 的形状定案:胶囊单选组,直接取 2c 顶栏导航那一枚(容器 #f5f5f5 + 1px #e0e0e0 + r7 + 2px 内边距;选中 = #ffffff 底 + 1px #e0e0e0 + r5 + 600)。唯一改动:选中文字换品牌色 #2563eb(桌面 hover 本来就是这个色)—— 卡内没有导航语义,需要一个「当前是哪一页」的强指示。不做下划线 tab:右栏的 Timeline / Chain View / Lifecycle Map 已经占了「方角 tab 条」这个形状,卡里再来一套会被读成第二个面板。
· 卡底:可选,只有 ≤ 5 条链接(13px 品牌色文本链接,↗ 只给站外)+ 至多一枚动作按钮(ghost 32 高 r7,照 2g 的 GitHub ↗)。按钮文案由模型给;点了只做一件事 —— 把那句话放进输入框、不发送,与 4f / 4v 的 Ask why 预填是同一个机制。卡底与主体之间 1px #e0e0e0 分隔。
· 卡片留在最终回答里:它是回答的一部分,不进折叠行。折叠行折的是「中间说的话 + 工具卡」;信息卡写在最终回答的正文里,模型写在哪就在哪(可以夹在两段话之间,也可以收尾),每次回复最多两张。本板故意画成一轮已完成态(折叠行收起,2l 画法),就是为了证明这一点。卡片级没有「查看轨迹」入口 —— 卡不是工具调用,没有对应的事件行。
· 本轮没有失败的工具调用,所以折叠行行尾不画 6px 红点(2l 规则原样生效)。中栏一次画满 = 实际是滚动区的一次全量展开;右栏事件流不随之拉长,固定贴顶。
· 卡宽 = 会话区正文宽度 640,卡内不横滚(桌面够宽);表格四列 226/128/96/188 = 638 是按内容排的定宽,不是弹性列 —— 同一张卡换列排序时列宽不动,只换行序。移动端的横滚与堆叠规则见 4y。
· 交互只有四种:tabs 切换、折叠 / 展开、表头排序(升 / 降)、单选切面板。三者都不做动画 —— 现有三个动效(omPulseBg / omWaveSweep / omSpin)语义都是「还在跑」,拿来做切换会撒谎。没有可编辑单元格、没有表单、没有会发请求的东西、没有「复制卡片」、没有「导出」、没有图表 / 图片 / 图标 / 进度条。

2t · 裁定
· 流式骨架的显示条件:正文流到 ```xray-card 这一行、围栏还没闭合的那段时间里显示;围栏一闭合就整块换成卡(或换成回落代码块)。骨架不预测行数 —— 固定一条标题条 + 三条正文条,因为围栏里那段 JSON 还没读完,行数与 kind 都还不知道。
· 骨架规格照 2i:文本条 r4、标题条 r6、卡片外框 r7 那一档在这里让位给卡片自己的 r6(外框就是最终卡的外框,不是骨架的一部分,所以它一开始就用最终态)。骨架色降一档:叠在 rgba(0,0,0,.03) 灰面上用 #e0e0e0,不用 #eeeeee —— 与 2i 「骨架叠在灰面上降一档」同一条规则。omPulseBg 只挂标题条一处锚点,三条正文条静止。
· 回落规则:JSON 解析失败 / 超限(行数、列数、字数、tabs 数量)/ 未知 kind,一律渲染成普通代码块,语言标签就是围栏名 xray-card,正文是那段原始文本。没有错误提示 —— 不画红条、不写「卡片渲染失败」、不给「重试」。理由:对访客来说这就是模型写了一段代码块,是完全正常的 markdown;对我来说原文还在,足够排查。代码块继承 2c 的既有画法(r7 外框 + #f5f5f5 头部条 + mono 11/650 语言标签 + mono 12/1.7 正文),连它本来就有的 copy 一起继承 —— 这不是「复制卡片」,是代码块的既有能力。
· 交互态三连:① tabs 切页 = 只换主体,标题行、胶囊组位置、卡底一律不动,选中胶囊 #ffffff 底 + 品牌色 600;② 排序 = 表头文字旁 10px 箭头(降 ˅ / 升 ˄),当前排序列整格转品牌色,其余三列常态 #1a1a1a、hover 才转品牌色,列宽与行高一字不动;③ 折叠 = 箭头 › → ˅,主体在标题行下方展开,标题行自身的字号 / 颜色 / 内边距不变。三种都不做动画。
· 段③-3 画的是 2s 里那张 collapsed 的 kv 卡点开后的样子,两块成对。collapsed 是卡片级状态,与 kind 无关 —— 六种主体都可以带 collapsed,list 与 table 的收起态与这里一模一样(标题行 + › 箭头),所以不再各画一遍。
· 段②③ 只画中栏正文列(640 + 左右 20 内边距 = 680),外壳与右栏省略 —— 这三样东西都只发生在正文列里,重画三遍三栏骨架只会让人以为哪里不一样。段① 保留整屏,因为它要同时给出「发送按钮转圈 + 右栏末行扫光 + 卡片骨架」是同一时刻的三个视图。
· 卡片留在最终回答里:段① 的骨架长在最终回答的正文里,不在折叠段里;这一轮跑完后折叠行收起,卡片留在原位(见 2s)。

标本⑧choice 卡的流式骨架 = 2t 的卡片骨架,一字未改
2u · 裁定
· 这不是第三种卡:两种新 kind 长在 2s / 2t 的信息卡语汇上,一处未改 —— 外框 r6 + rgba(0,0,0,.03) 底 + 1px #e0e0e0 中性描边、标题行 mono 10/600 #9ca3af 0.08em(可选)、卡底 1px #e0e0e0 分隔 + 一枚 ghost 32 高 r7 按钮。唯一新增的两个形状是选择指示:单选 15px 圆点 / 多选 15px r4 方框,常态 1px #e0e0e0 描边 + 白底,选中态描边与填充都换品牌色 #2563eb(多选内嵌 9px 白色对勾)。卡里一处不用语义色。
· 解剖与上限:choice = 可选 title(≤60)+ 可选 prompt 题干(≤200,13/1.7 次级色,压在标题行下、选项之上)+ 2–8 个 options(label ≤60 正文色 13/1.7、可选 note ≤200 的一行 11 #9ca3af)+ multiple 真假;form = 可选 title / prompt + 1–5 个 fields(label ≤40、type 只有 text 与 select、placeholder ≤100、select 2–8 项、required 真假),text 最多 100 字。按钮文案 ≤20,缺省「提交」。选项行 padding 9/12、行间 1px #e0e0e0,输入框照 1a 底部那一枚缩小版(1px #e0e0e0、r7、32 高、13px,聚焦描边转品牌色)。
· 发送规则:单选没有按钮 —— 点任一选项即刻发出并锁定(少一次点击,也少一个「选了但没提交」的中间态);多选与 form 靠卡底一枚 submit 发出,禁用条件:多选至少选中一项前禁用、form 必填字段填满前禁用。禁用视觉 = 文字降到 #9ca3af、描边与底色不变、无 hover、cursor:default —— 与底部发送按钮的禁用是同一副。
· 发出去的就是一条普通访客消息:气泡照 1a(#eff6ff 底 + 1px rgba(59,130,246,.2) + r12 + 14/1.7),没有任何「来自卡片」的标记,没有「已发送」字样、没有撤回。消息文本的组成:choice = 题干 + ASCII「: 」+ 所选 label(多选之间用「、」);form = 题干 + 空格 + 「字段: 值」以「; 」相连。发出的字都是卡上看得见的字 —— title / note / placeholder / 按钮文案一律不进消息;没有题干时消息从第一个 label(或第一个「字段: 值」)起头。
· 锁定态:选项与输入框不可再点、已选高亮原样保留、未选的 label 降到 #9ca3af、按钮回到禁用视觉、文案不变(仍是「提交」,不改成「已提交」)。busy 态:上一轮还在生成时,卡上的选项与按钮和底部发送按钮同时禁用(标本⑦ 把两者画在同一框里就是为了对齐这副视觉)。两种态都不做动画 —— 现有三个动效语义都是「还在跑」。
· 选中与锁定都是本地状态:刷新后回到初始态,老卡又能点。理由:服务端不存卡片答案,存的是那条已经发出去的访客消息 —— 它就在会话里,谁都看得见。
· 位置① = 折叠行之后、最终正文之前;位置② 见 2v(最后一段正文之后)。每轮最多两个组件,任意组合。卡片留在最终回答里,不进折叠行;卡片级没有「查看轨迹」入口(它不是工具调用)。
· 流式骨架(标本⑧)与回落规则照 2t 原样:```xray-card 开围栏 → 卡框先立住 + 一条标题骨架条(r6,omPulseBg 唯一锚点)+ 三条正文骨架条(r4),骨架色叠在灰面上降一档到 #e0e0e0;围栏闭合 → 原位换成卡;JSON 写坏 / 超限 / 未知 kind → 普通代码块(语言标签 xray-card),没有错误提示。
· 画板上没有的功能不画:没有校验错误文案、没有数字 / 日期 / 多行输入、没有上传、没有步骤条、没有「已发送」「发送成功」、没有撤回、Timeline 里也没有卡片事件(点选项产生的是一条访客消息,轨迹与手打一条消息完全一样)。

2v · 裁定
· 帧是一个 sandbox <iframe>:里面不执行脚本、不发任何网络请求、没有链接、没有图片、点不出任何东西,唯一的交互是 <details> 折叠。只有排版:标题 / 段落 / 表格 / 列表 / 代码 / 内联 SVG / <details>。帧里点什么都不会发消息 —— 要让访客回话是 choice / form 的事(见 2u)。
· 外框照工具卡展开体 / 代码块:r7 + 1px #e0e0e0,帧内容不另画外框(套第二层会出双线)。帧上没有标题栏,也没有「全屏」「复制」「在新窗口打开」「刷新」 —— 它是正文的一部分,不是一个应用窗口。
· 宽 = 正文宽(桌面 640,移动 358);高由模型在开围栏行声明,夹到 160–480(移动 ≤ 360),缺省 320。内容超高在帧内滚(系统滚动条),页面不跟着长;内容不足则帧仍按声明高度立住,底部留白。
· 帧内文字与配色跟随站点主题:帧里注入站点的颜色 / 字体变量,所以它看上去像正文的延伸,只是被一圈边框圈住 —— 正文 #1a1a1a / 次级 #6b7280 / 弱化 #9ca3af / 面 #f5f5f5 / 边框 #e0e0e0 / 品牌 #2563eb / 等宽 JetBrains Mono,一处不越界。
· 流式:开围栏行一到,高度就定了 → 先显示按那个高度立住的骨架(外框 + 三条 r4 骨架条 + omPulseBg 一处锚点);围栏闭合 → 原位换成帧;不做渐进渲染(半截 HTML 渲出来会闪成另一种版式),换入不做动画。
· 回落:写坏 / 超过 16 KB → 普通代码块(2c 画法:r7 外框 + #f5f5f5 头部条 + mono 11/650 语言标签 xray-html + mono 12/1.7 正文 + 既有的 copy),没有错误提示、不写「渲染失败」、不给「重试」。对访客来说这就是模型写了一段代码块,是完全正常的 markdown。
· 位置② = 最后一段正文之后;位置① = 折叠行之后、正文之前。组件只能在最终回答的首或末,每轮最多两个,任意组合(可一首一尾,也可同在一处)。组件不进折叠行,Timeline 里也没有组件事件。

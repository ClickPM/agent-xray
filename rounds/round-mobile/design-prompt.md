### 三条必须先认下来的技术事实(它们改变了画板内容)

1. **微信 webview 里 PWA 三件套全部失效。** Service Worker 在微信内置浏览器不可用,manifest 不会被读,
   没有安装入口。manifest 与 `display: standalone` 的意义只剩一件:访客**自己**在 Safari/Chrome 里
   「添加到主屏幕」之后能全屏启动 —— 我们不引导,但留着这条路。**所以画板必须以「微信 webview 里长什么样」为准绳画**,
   standalone 是附带态。
2. **微信自己的顶部导航栏(约 44pt,显示页面标题)无法隐藏。** 微信 webview 没有地址栏、没有底部工具栏,
   但顶部这条微信原生栏一直在。**画板必须把它画成占位区**,否则我们的玻璃导航条会和它叠成两层标题栏。
3. **网页锁不了屏幕方向。** `screen.orientation.lock()` 只在全屏或已安装态可用,微信 webview 与
   iOS Safari 都拿不到。「竖屏」只能落成 CSS 降级:横屏时维持竖屏版式、限制最大宽度居中。
   请在 `4u` 画出这一态。

## 提示词正文(从这里开始复制;P0 批)

新建一份画板集,文件名 **`Agent X-Ray Mobile`**。这是一个**已经投产的桌面站**的移动端设计,
桌面端的 20 块画板(`1a`–`1g`、`2a`–`2m`)是终稿、已实现、**这次一个像素都不动**。
移动端是另起的一套,与桌面并存。

### 0. 这个站是什么(不了解产品画不出对的东西)

**Agent X-Ray**:访客与一个 AI agent 对话,同时像 DevTools 一样**实时看到 agent loop 的内核轨迹**
(34 种扩展事件)。它的卖点就是「内核可见」。四个顶部 tab:

- **Runtime 工作台**:桌面是三栏 —— 左 260px 会话列表 / 中 会话区(对话 + 工具调用卡 + 输入栏)/
  右 42%(min 300 / max 500)运行时面板,面板内四个 tab:**Timeline**(事件流,每行带一条按耗时定宽的色条)/
  **Chain View**(扩展链路)/ **Lifecycle Map**(生命周期节点图)/ **Tools**(工具能力说明,只读)
- **Notes 研习库**:分类 → 系列 → 章节。章节页是 markdown 长文,桌面为 `720px 正文 + 右侧悬浮「本章目录」`
  双栏,顶部有一条阅读进度线
- **Skills 技能库**:卡片列表 → 详情页。详情页桌面为 `左 240px 粘性目录树 + 右文件预览`,
  预览分两态:`SKILL.md`(frontmatter 键值块 + markdown 正文)与 `.py`(带行号的代码视图)
- **About**:关于页

现有视觉语言 —— **克制的开发者工具风**:白底 / 浅灰面 / 1px 实线边框 / 小圆角(4–12)/
唯一品牌蓝 `#2563eb` / 等宽 **JetBrains Mono** 承载所有数据。深色模式已有。

### 1. 最重要的一条规则:两层语言,各管一半

移动端**不是**把桌面站等比缩小,也**不是**给整站套一层 iOS 皮肤。分两层画:

- **外壳层 = iOS 26**:顶部功能条、底部 Tab Bar、Sheet 与弹层、按钮、分段控件、列表行、
  页面转场、空状态、加载态、错误态。这一层**完全按 iOS 26 的语言重画**。
- **内核层 = 保留现有 DevTools 语汇**:Timeline 的事件行与耗时色条、Chain View 的链路、
  Lifecycle Map 的节点图、工具调用卡、代码视图与行号列、`SKILL.md` 的 frontmatter 块、
  markdown 正文排版。这一层**只做尺寸、触控与换行的适配** —— 颜色、字体、边框、语义色、
  卡片解剖**照搬桌面 token,一字不改**。

**为什么**:这个站卖的就是内核可见。把 Timeline 做成 iOS 标准列表,它就不是 X 光机了。
玻璃与胶囊负责「这是一个 iOS App」,密集的 mono 数据负责「这是一台 X 光机」。

**两层的接缝要画清楚**:内核层永远装在一个 iOS 容器里,**容器是 iOS 的,内容不是**。
请在每块含内核层的画板上,把这条接缝用标注线指出来。

### 2. 载体:社交 webview 优先(这一节决定了很多取舍,先读)

站点**主要在微信等社交 App 的内置浏览器(webview)里打开**,其次是移动浏览器直接访问。
这不是普通的响应式网页,以下每条都会改变画法:

- **顶部永远有微信自己的导航栏**(约 44pt,状态栏之下,显示页面标题,**网页无法隐藏、无法改色**)。
  **每块画板都要把它画成占位区**(浅灰虚线块 + 标注「微信导航栏 · 不可控」)。
  **由此产生一条设计裁定**:我们自己的顶部条**不是标题栏,是功能条** ——
  它不重复显示页面标题(微信已经显示了),只放左右两个功能按钮和必要的状态。
  请在画板上写明这条取舍。
- **微信 webview 没有地址栏、没有底部工具栏** —— 所以底部 Tab Bar 可以放心贴底,
  这是社交 webview 相对普通浏览器的优势。但在 Safari 里会与浏览器工具栏叠,`4u` 画这一态。
- **玻璃材质必须有降级方案**。Android 微信用的内核对 `backdrop-filter` 支持不确定。
  请为每一处玻璃**同时给出两套值**:
  - 支持时:`rgba(255,255,255,0.72)` + `backdrop-filter: blur(24px) saturate(180%)`
  - 不支持时:**实底 `rgba(255,255,255,0.94)`** + 底缘 1px `rgba(0,0,0,0.06)` 分隔线
  在 `4u` 画一张「降级态」对照图,证明降级后版式不塌、层级仍清楚。
- **字体在 Android 上拿不到 SF**。字体栈写成
  `-apple-system, BlinkMacSystemFont, "PingFang SC", "Microsoft YaHei", sans-serif`,
  并标注:iOS 上是 SF、Android 上是苹方 / 系统黑体,**字号与行高按两种字体都能站住的值取**
  (中文正文 15/1.75,别用 iOS 专属的紧行距)。**mono 数据仍是 JetBrains Mono**(站点自托管,两端一致)。
- **可视高度要扣**。390×845 的屏,微信里真正归我们的内容高度 ≈ 845 − 59(状态栏) − 44(微信栏) − 34(Home Indicator) ≈ **708**。
  **画板仍按 390×845 出**(这是你给的标准模板),但把上述三块画成占位区,
  并在画板上标出**内容安全高度 708** 这条线。首屏要放的东西按 708 排,不按 845 排。
- **禁用双指缩放**:画板上每屏标注「本屏不可双指缩放」,并据此保证:正文最小 15px、
  mono 数据最小 11px,且**代码块 / 宽表 / Timeline 色条 / 安装命令行在各自的盒子里横滚**,页面本身永不横滚。
- **横屏做不到硬锁**:`4u` 给一态降级 —— 横屏时维持竖屏版式、最大宽度 430 居中、两侧留白。

### 3. iOS 26 视觉语言的具体落法

静态画板里怎么把 Liquid Glass 画对:

- **材质**:见上一节的「两套值」。玻璃与降级两态都要有。
  深色玻璃 `rgba(28,28,30,0.72)`,降级实底 `rgba(28,28,30,0.94)`;
  顶缘 1px 内高光 `rgba(255,255,255,0.5)`(深色 `rgba(255,255,255,0.12)`);
  外投影极轻 `0 1px 12px rgba(0,0,0,0.06)`
- **全站只有三处用玻璃**:① 顶部功能条 ② 底部 Tab Bar ③ Runtime 的输入栏。
  **内容卡片一律实底**,否则整页发糊、数据读不清
- **控件浮在内容之上**:内容 edge-to-edge 延伸到玻璃底下(滚动容器上下各留出与玻璃等高的内边距)。
  滚动到顶 / 到底时玻璃后面能看见内容边缘 —— 这是 iOS 26 的关键观感
- **圆角同心**:外层容器圆角 R、内边距 P,则内部元素圆角 = R − P。阶梯表:
  Sheet 20 / 分组卡 16 / 卡内元素 10 / 徽标与 chip 全圆(胶囊)/ 输入框全圆
- **胶囊**:主按钮、次按钮、分段控件、标签、徽标一律 full-round;**内容卡片不是胶囊**
- **大标题**:每个 tab 的一级页(Notes 首页 / Skills 首页 / About)用 iOS 大标题 34px/700,
  向上滚动时收进功能条变成 17px/600。**注意微信里上方还有一条微信标题栏** ——
  收起态不要再出现一个居中标题,改为**左对齐的小标题**,避免与微信栏形成两个居中标题。请标注这条
- **分段控件**:运行时面板的四个 tab 用它
- **Sheet**:两档 detent —— medium ≈ 内容安全高度的 50%、large ≈ 92%;
  顶部 grabber(36×5、`rgba(120,120,128,0.4)`、圆角 2.5);圆角 20 只在上两角;背后内容轻微缩放并压暗
- **列表**:iOS inset grouped —— 分组卡圆角 16、左右外边距 16、组内行高 56、
  行间 1px 分隔线从左内边距 16 起(不通栏)、行尾 chevron `#c7c7cc`
- **触控**:所有可点元素命中区 ≥ 44×44pt;按下态 = 底色加深一档 + 0.97 缩放
- **动效**:转场用 iOS 默认曲线;**现有三个动画照旧保留、不新造** ——
  `omPulseBg`(Lifecycle 活跃节点)/ `omWaveSweep`(Timeline 进行中行的扫光)/ `omSpin`(生成中转圈)

### 4. 尺寸与栅格(硬约束)

- **基准画板 390 × 845**,每块画板都按这个尺寸出;上方画出状态栏 59 + 微信导航栏 44 占位,
  下方画出 Home Indicator 34 占位,标出**内容安全高度 708**
- **左右内边距 16**;分组卡内边距 16;垂直节奏取 8 的倍数
- **动态布局(硬要求)**:所有横向尺寸用比例 / `min()` / `max()` / flex,
  **不许出现任何依赖 390 的写死宽度**。每块画板下方必须标注:在 **320**(iPhone SE)与
  **430**(Pro Max)两个宽度下**哪个元素吸收差值、哪个保持不变**
- **高度也要动态**:微信栏高度、状态栏高度、有无 Home Indicator 各机型不同。
  首屏内容不许假设 708 是定值 —— 标注「哪一块是弹性的、哪一块固定」

### 9. 明确不做(越界的一律不画)

站点范围以既有画板为准,移动端**只换呈现、不加功能**。以下一个都不许出现:

- Skills / Notes 的**搜索、筛选、点赞、评论、安装量、排序**(桌面裁定过:整个 Skills tab 只读)

- **「添加到主屏幕」引导**(所有者裁定不做)
- 任何桌面站没有的数据字段

移动端**允许新增的只有交互原语**:Sheet、左滑、下拉刷新、大标题收起、键盘避让,
以及 `4u` 的载体适配态。
